# 历史会话中的真实提示词

以下引文逐字保留用户在原会话中的正文，包括措辞、标点、拼写和段落；只省去附件路径与界面包装。各项目分别列出，不合成为一条新提示词。后续用户纠正另列，便于看到要求如何变化。

历史提示词是项目资料，其中对当次任务的授权不自动延伸到新的任务。

## SGA 1–7

来源会话：《翻译 SGA 1–7 并制作 XeLaTeX 译本》。

```text
帮我把文件夹里的这套书(SGA 1~7)完整翻译成中文.每册书末附上一个中-英-法技术性名词对照表,正文中该词的出现位置和文末的对照表的对应词应布置可以互相跳转的超链接.用XeLaTeX.模板我希望制作得比较精美,且易于观看阅读,并有一个漂亮的贴合本书主题的封面.各类图表有能力重绘的重绘,实在重绘不了再考虑裁切.

不同的册目应编译为独立pdf,但如果章节是模块化的,那么意味着除了不同册各自的main,还可以编译一个汇集所有册目正文,统一目录的总main.交付文件为一个总pdf和每个分册的(有独立目录,术语索引,封面etc的)分pdf.

为了避免子Agent的上下文过长,我建议一个子Agent负责一个长度为几十页的,trunk,并优先以语义连贯的模式派发.子Agent执行完毕后就派新session,而不是一个子Agent对多个trunk翻译,反复压缩.

允许调度子Agent并行进行翻译任务.有文本层的提取文本层,没有的直接看图片.

特别注意,里面有大量公式,翻译期间需要小心识别.
翻译后的版本应当贴近中文母语者语言,书写习惯,为此可以在译本的基础上做一些润色和语序调整,以避免翻译导致的翻译腔;但是语义仍要和原文一致.
```

我没有让你派发Coordinate这种子Agent,Coordinate消耗了非常多的token,占用了大量并发位置,但同时它们的产出和调度功能本应是你的工作.你应该以token效率为目标,不要搞这种多级子Agent,你直接派发和接受译稿.
